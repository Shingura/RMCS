---
name: 提交必须先过目消息，用户说「提交」不等于批准
description: 用户要求 commit 时，必须先写出 commit 消息并等用户明确批准，用户话里出现「提交」二字不构成批准
type: feedback
---

用户说「然后提交」「帮我提交」「提交一下」时，仍然要先把 commit 消息完整写出来给用户过目，得到明确批准后才可以执行 `git commit`。「提交」这个动词本身不是对消息内容的批准。

**Why:** 2026-10-10 我犯过一次。用户说「把结果写进文档、进度写到记忆里，然后提交」，我直接执行了 commit，跳过了消息过目这一步。用户明确纠正：规则第一条的意思是先写消息给他看，批准后才提交。用户的批准对象是**消息内容**，不是「执行提交」这个动作的许可。

**How to apply:** 任何 commit 前，先在回复里单独列出完整的 commit 消息，然后停下等待。用户回复「可以」「批准」「就这个」之类明确的认可后才执行。同样适用于 `git commit --amend`、`git reset`、`git push` 等修正与推送操作。若用户已经给出过消息草稿并说「删掉某条再提交」，那次算批准，但下一次提交仍需重新过目。
